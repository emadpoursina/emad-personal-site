# Agent-readable output contract — Phase 2

**Spec**: [../spec.md](../spec.md) · **Plan**: [../plan.md](../plan.md) · **Data model**: [../data-model.md](../data-model.md)

Four surfaces carry the profile to machines. All four are generated by `src/lib/agent-output.mjs` from `content/profile.json` and `content/case-studies.json`; none is hand-maintained.

## 1. `/resume.json` — JSON Resume v1.0.0

**Schema pin**: `https://raw.githubusercontent.com/jsonresume/resume-schema/v1.0.0/schema.json`
**Vendored copy**: `schemas/jsonresume-v1.0.0.json` (14,945 bytes, sha256 `ff6e39e79cfe6dedddf7c1e313ddb4da346bde8b055a884d7f6d849965dc27a6`)
**Validator**: `ajv@8` + `ajv-draft-04@1`, dev-only, `{ allErrors: true, strict: false, validateFormats: false }`

The response MUST validate against the schema and MUST equal `buildResume(profile, studies)` byte-for-byte (both checks run; conformance alone is insufficient because the schema declares no required fields).

```json
{
  "$schema": "https://raw.githubusercontent.com/jsonresume/resume-schema/v1.0.0/schema.json",
  "basics": {
    "name": "Emad Poursina",
    "label": "AI and Agentic Systems Engineer with a strong foundation in software development",
    "email": "emad.poursina.work@gmail.com",
    "summary": "Software engineer with 7+ years of production Node.js work, …",
    "profiles": [
      { "network": "LinkedIn", "url": "https://www.linkedin.com/in/emadpoursina/" },
      { "network": "GitHub", "url": "https://github.com/emadpoursina" }
    ]
  },
  "work": [
    {
      "name": "Hamed Mosaddeghian",
      "position": "Technical Lead",
      "startDate": "2019-03",
      "endDate": "2023-12",
      "highlights": ["Led development and maintenance of web platforms.", "…"]
    }
  ],
  "education": [
    { "institution": "Yazd University", "studyType": "Associate Degree", "area": "Computer Engineering", "startDate": "2019", "endDate": "2023" }
  ],
  "skills": [{ "name": "Node.js" }],
  "languages": [{ "language": "Farsi (Persian)", "fluency": "Native" }],
  "projects": [{ "name": "AgenticCoding", "description": "…", "url": "https://github.com/emadpoursina/agenticCoding" }],
  "meta": { "version": "v1.0.0" }
}
```

Rules:

- `work[].endDate` is omitted for an ongoing role (`present` is not an ISO-8601 value in the schema).
- No skill `level` is emitted (levels belong to `/api/profile`; F7 AC3).
- No empty-string `url`; profile projects with `url: ""` omit the field.
- `projects` = the six profile projects in order, then every published case study in content order (draft never appears).
- `last_updated` is not present at the top level (`additionalProperties: false`).
- Doubles as the static source for `application/json` at `/resume.json`.

## 2. `/api/profile`

```json
{
  "last_updated": "2026-11-08",
  "basics": { "…": "same as resume.json" },
  "work": ["…"],
  "education": ["…"],
  "languages": ["…"],
  "projects": ["…"],
  "skills": [{ "name": "Node.js", "level": "Expert", "category": "Backend" }],
  "meta": { "version": "v1.0.0" }
}
```

Contract:

- Exactly `resume.json` with `skills` enriched by `level` and `category` (profile order), plus top-level `last_updated`.
- `last_updated` equals `profile.lastUpdated` (ISO `YYYY-MM-DD`), never the request time.
- Deep-equal of every non-`skills`, non-`last_updated` key against `resume.json` is asserted by two independent checks: `check-agent-output.mjs` compares the pure builders, and `test-public-routes.mjs` compares the live responses.
- `Cache-Control: public, max-age=300`; `Content-Type: application/json; charset=utf-8`.
- No draft case-study fact (the only place it could appear is `projects`, already filtered).

## 3. `/llms.txt`

`text/plain; charset=utf-8`, exact section order from the data model: title, blockquote headline, target roles, work authorization, availability, published case-study URLs, CV URL, contact URL + email. Draft studies are absent. Absolute URLs use the configured site URL. The check asserts every required line and the absence of any draft slug; it does not assert a specific host, so the local default does not weaken it.

## 4. Person JSON-LD (every rendered HTML page)

Injected once by `src/layouts/BaseLayout.astro`; `check-agent-output.mjs` walks `dist/client/**/*.html` and asserts:

- exactly one `<script type="application/ld+json">` per page, and no other `<script>` element or `src`;
- the parsed object deep-equals `buildPersonJsonLd(profile)`;
- `@context` is `https://schema.org`, `@type` is `Person`;
- `name`, `jobTitle`, `email` are the approved strings;
- `sameAs` is exactly `[profile.links.linkedin, profile.links.github]`;
- `knowsAbout` equals the names of skills whose level is `Intermediate`, `Advanced`, or `Expert`, in profile order — exactly **36** names, and no `Beginner / Learning` entry;
- the serialized block contains no draft slug or draft URL.

## 5. `/sitemap.xml`

`application/xml` with UTF-8 declared in the XML prolog (prerendered `.xml` is served by the adapter's static path, which adds no charset parameter — W1); fixed order `/`, `/about`, `/case-studies`, `/contact`, then published studies in content order. Absolute URLs from the configured site URL. No `<lastmod>`. Draft slugs absent. The check parses the XML and compares the URL path list exactly.
